# Homework 5 — Campus Customs Multi-Agent Operations

A campus apparel shop run by a team of five AI agents, with a human in the loop
for anything that costs money.

- **MCP server** (`mcp_server/`) — 16 tools over the shop database; every shop
  fact and every shop write goes through it.
- **FastAPI backend** (`backend/`) — 15 routes, and the five-agent team built
  with PydanticAI on `gpt-6-luna` via Portkey.
- **React dashboard** (`frontend/`) — the operations desk a human watches and
  approves from.

## Setup

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cd frontend && npm install
```

`PORTKEY_API_KEY` is read from the **workspace-root** `.env` (not committed).

## Running

```bash
cp data/campus_customs.db data/campus_customs_new.db   # reset to opening state

cd backend  && uvicorn main:app --reload --port 8000
cd frontend && npm run dev                             # http://localhost:5178
```

`.mcp.json` registers the MCP server for Claude Code.

## The data

`data/campus_customs.db` is the **pristine master** and is never written to.
All work happens on `data/campus_customs_new.db`, which is gitignored because it
is regenerated by copying the master.

Opening state: $3,400.00 in checking, an $840.00 invoice 3 days overdue,
$2,400.00 rent due in 2 days, three open tickets.

## The rule that matters

No agent can approve a payment. `decide_approval` is filtered out of the agents'
toolset, so the only way cash moves is a human clicking approve on the board —
and `pay_approved` refuses anything unapproved, unaffordable, or already settled.
